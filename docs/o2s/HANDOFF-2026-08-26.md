## 6. Things worth knowing before touching this code

- **`hardRole(roles)` must never consult the access matrix.** On 30 July a screen Edit
  grant silently bought Dispatch-Clearance approve and release authority. That is the
  incident the whole rights model is shaped around.
- **Sign-off gates stay on raw `hardRole` and must never become rights**: `coaReview`,
  `coaApprove`, `coaDeviation`, `coaRework`, `approveDC`, `rejectDC`, `approveRelease`,
  `doReopenBatch`, `openReopenBatch`.
- **`batchStage` is deliberately never touched.** A batch has one status decided by its
  worst part. Changing it moves the step dots, the reconcile list and several counts.
  When something needs a different question, add a new function — that is what
  `batchPackNow` is.
- **`may('right')` answers from the grant table only if the right is in `RIGHTS_LIVE`
  (currently empty), otherwise it runs the recorded `legacy`** — byte-equivalent to the
  check the gate ran before conversion. That is the freeze, and every review re-proves it.
- **`state.masters.roleRights` is keyed by role ID, not name.** A role name with an
  apostrophe once broke its own tick button.
- **Two different questions, easy to confuse**: `mayRole`/`may` is the exact old,
  screen-dependent answer used by real gates. `rightAnswerToday`/`mayHere` is the
  screen-independent answer, used only by the Authorisation panel and its helpers.
- **The live database is on HostGator behind Render and is unreachable from a session.**
  `data/state.json` is a 16 July local snapshot, used only as a test fixture.
- **Nothing in a session container survives.** Anything worth keeping goes to
  `E:\VAN-OP`.
