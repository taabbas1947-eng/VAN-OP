# HG26025 — produced 38,800 but only 35,400 ready to pack
**25 August 2026 · delivered to E:\VAN-OP, reviewed and approved before delivery**

## What actually happened

Production is right. The batch made 38,800 Kg. The app was holding 35,400.

Lots are only ever created in one place — when a shift log is submitted — and that
same line adds the shift quantity to the batch's Produced total. So the two can only
drift apart in one other place: when a production entry is **voided**.

A 3,400 Kg entry on HG26025 was voided **after the lab had already certified its lot**.
The void code refuses to delete a certified lot (correct), but it went on to subtract
the 3,400 Kg from Produced anyway (wrong). The lot stayed, the quantity left.

35,400 + 3,400 = 38,800.

## What was changed

**1. Voiding a certified entry is now refused up front.**
Before any change is written, the app checks whether the lab has approved a COA on the
matching lot. If it has, the void is refused with an explanation: certified material
cannot be un-logged — if it has gone, dispose of it. Nothing is half-done any more.

**2. A proper correction exists for Produced.**
On the batch passport, and on the Closed batches card, there is now a **Correct…**
button. Plant Manager and COO can correct **Produced (Kg/L)**. It needs a reason, it
goes in the correction register with before → after, who did it and why, and it reports
back what the batch can now pack.

The correction refuses anything that would be a lie rather than a repair:
- below what has already been packed or disposed
- below what the lab has certified
- on a multi-PO batch (allocation, not a single number)
- above the total of the batch's own lots — that means a shift is missing, so log the
  shift instead
- to nothing, on a batch that has lots

**3. The PO line is kept in step.** Correcting a PO-linked batch now also moves the
order line's produced figure, so the over-run guard sees the right remaining quantity.

**4. Reversing a batch in the register is switched off.** It was writing a record that
said "reversed" while doing nothing at all.

## How to repair HG26025

1. Open the batch (Closed batches card, or the batch passport).
2. Click **Correct…** — you need to be signed in as Plant Manager or COO.
3. Pick a reason, set **Produced (Kg/L)** to **38800**, submit.
4. It will confirm: *Ready to pack is now 38,800 Kg*.

## One thing you will see straight after, which is not a new fault

The Closed batches banner will say *"1 of these recorded a yield that no longer matches
what the batch produced"* and suggest reopening and re-closing. **Ignore it.** The yield
figure was frozen when the batch was closed and the check compares it against the
corrected Produced. It is a false alarm and it is first on the fix list.

## Still open on this (none of it blocks the repair)

1. The false yield alarm above.
2. The multi-PO refusal points at a PO-line field that does not exist.
3. The certified floor ignores disposed material, so certified stock can be stranded.
4. The PO mirror has a floor but no ceiling — it can push a line past ordered.
5. The unconditional subtraction in the void code is still there for the case where no
   lot matches at all.
6. `doReopenBatch`'s comment about REVERSE authority is now false.
7. Data Fix raises Produced without creating a lot, which breaks the "Produced = sum of
   lots" premise the correction relies on.
