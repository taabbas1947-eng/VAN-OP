Material register

The single controlled list, held at grade level — because "MAP" is not something you can put in a recipe, "MAP 11-52 imported" is. Every combination line points at one of these ids, which is why the duplicate check is exact rather than a guess at spelling. Only a moderator adds to this list.

Each material also carries a "grade not yet decided" placeholder. Idea-stage work often predates the sourcing decision, and forcing a grade that early would either stall the idea or put a fictional grade on record. A recipe holding a placeholder is fully searchable — it simply can never be hard-stopped as an exact repeat, because nobody can prove it is one.
This must be PD's existing pd_materials table — the one the candidate screen already uses for pd_candidate_lines — not a second list. Two material registers drift apart within a month and the costing arithmetic stops agreeing with the bank.

How the duplicate check works

  
Hard stop only on clear evidence; anything less comes in, flagged, and a moderator settles it. Nothing is ever refused because the app was unsure.

  

    
Grades — where a naive check would block honest work

    
A material is not one thing. MAP has several grades, phosphoric acid has more. Three rules follow, and each exists to stop a false block:

    
SituationRule

      
Same material, two grades, one recipe
MAP 11-52 + MAP 10-50 in one blend		Allowed, no warning beyond a note. They are different materials with different assays and different prices. A rule of "MAP cannot repeat" would block a legitimate blend, so the rule is on the grade, never the substance.

      
Same grade twice in one recipeAlmost always an arithmetic slip. Flagged with a one-click merge — never blocked.

      
A grade is not decided yetPick the placeholder. The row saves and is searchable. It can never be hard-stopped as a repeat: two recipes holding a placeholder may look identical and be different things, and the app will not assert something it cannot prove.

      
Two recipes, same substances, different gradesVariant, not a duplicate. Swapping 52% phosphoric acid for 61% is a real experiment with a real cost consequence — treating it as a repeat would erase the finding.

    

    
Net effect: the hard stop needs every line on both records to name a real grade. Anything less falls to the queue. The failure direction is always "ask a person", never "refuse a person".

  

  

    
What changed now that composition is material rows

    
The fingerprint is no longer a string. It is the sorted list of material_id : inclusion% plus form and route. Two records either have the same materials at the same inclusions or they do not — there is nothing to interpret.

    
no name-matching at runtimeno synonym riskno "humate vs humic acid" problem

    
The alias table survives in exactly one place: mapping names inside an imported file to register ids. An unmatched name there parks the row for a moderator; it never invents a material. So the old failure mode — a bad alias causing a false hard stop — is gone from the live path.

  

  

    

      
The four bands

      
BandWhat the app does

        
IdenticalClear evidence — hard stop. Same material ids, same inclusions (±0.5%), same form, same route, same problem. Does not save. One way through: save as a repeat run, linked, with its own date and reason.

        
VariantSame materials, different inclusions — or the same recipe aimed at a different problem. Saves, flagged pending review. A ratio is the experiment, not a duplicate.

        
RelatedDifferent chemistry, same intent. Saves, flagged pending review.

        
ClearSaves straight in, confirmed, no flag.

      

    

    

      
Guards against a false accusation

      
    
        
  • Same recipe, different problem is not a duplicate — it is the same chemistry reached from another direction, which is the point of the bank.
    • 
        
  • A flagged row is a full citizen — in the bank and in search from the moment it is entered.
    • 
        
  • "Not the same, because…" is remembered — a dismissed pair is never raised again, for anyone.
    • 
        
  • The checker names its evidence, never a bare score. A person can argue with a reason.
    • 
        
  • Nobody is stopped by a missing material — request it, the row saves flagged, the moderator adds it once.
    • 
        
  • 3 days unactioned escalates into My Work. No auto-accept: a person decides, or it keeps asking.
