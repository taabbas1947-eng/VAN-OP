## Why this file exists

The original `E:\VAN-R&D` PHP app (`van-rd-app` v2.2, 182 passing assertions) was built by accident in the wrong working directory. The actual goal is for Product Development (PD) to live *inside* O2S — one codebase, one login, one deploy — not as a second system to keep in sync. This port treats the PHP app as a **tested functional spec**, not code to keep running. It has no real user data in it (only seed/test accounts), so there is nothing to migrate — just logic to carry over faithfully.

You chose "full port in one go" (don't put PD in front of users until it's complete) over shipping a slice at a time. This file exists so that promise is checkable rather than taken on faith: it is the honest, current gap between "what the PHP app does" and "what's built in O2S so far," updated as each piece lands.

## Folder structure

Everything PD-specific lives under this `pd/` folder, kept apart from the O2S files in the repo root — the whole reason this port exists is that the two got mixed up once already (the standalone PHP app built in the wrong directory). The only PD-aware code outside this folder is a few lines in the shared `server.js` (it has to be — one Express server serves both apps) and the PD card in `launcher.html`; everything else PD owns lives here:

```
VAN-OP/
  server.js          <- shared O2S + PD server (routes, auth, both apps' APIs)
  index.html          <- O2S frontend (untouched by this port)
  launcher.html        <- shared front door (O2S card + PD card)
  package.json, render.yaml, etc.  <- O2S/deploy infra (untouched)
  pd/                 <- everything Product Development
    pd.html            <- PD frontend
    pd-lib.js           <- PD business rules (lanes, gates, roles) ported from the PHP app
    PORTING_STATUS.md    <- this file
    migrations/
      001_pd_foundation.sql  <- PD's database schema (additive, same DB as O2S)
```

## What's built and verified (this session)

Verified: 29 statements apply cleanly on a fresh database and are safe to re-run.
- **Routing**: `/pd` now serves a real PD app (`pd.html`), fixed to route *before* O2S's catch-all — previously any path that wasn't `/` or `/launcher` silently served the O2S app, which would have swallowed `/pd` silently once the launcher card pointed at it.
- **Auth**: PD uses the exact same login (`POST /api/login`) and the exact same `van_token` in `localStorage` that O2S's `index.html` already uses. Signing into one signs you into both — this is the "one login" goal, achieved by construction rather than bridged.
- **Idea intake** (`POST /api/pd/ideas`): H-number allocation, lane set automatically from the kind of idea (submitter never sees or picks a lane) — ported from `lane_for()`/`HEAVY_TYPES` in `inc/db.php`.
- **G1 screening** (`POST /api/pd/ideas/:id/screen`): role- and lane-gated (`may_screen`), deputy screens correctly flagged `provisional` (`screens_as_deputy`), a written reason is required, a second screen on the same idea is rejected (409). **Correction made during testing**: the screening vocabulary is `log/park/kill/merge` (matching `hypothesis.php`'s actual form and `schema.sql`'s ENUM), not the `advance/park/kill/reclassify` labels in `db.php`'s `GATE_OUTCOMES.G1` constant — the original PHP app has that inconsistency between a constant and the live form; this port follows the form, since that's what's actually enforced. Documented in `pd-lib.js`.
- **Gate log** (`GET /api/pd/gatelog`) and **My Work** (`GET /api/pd/mywork`) — read-only views, role-gated the same way `inc/auth.php`'s `allowed_pages()` gated the PHP router.
- **Role assignment** (`PUT /api/pd/users/:username/role`, COO/admin only) — the bridge between an existing O2S account and PD access. Nobody has a `pd_role` until explicitly given one.
- **Records & G2** (`GET/POST /api/pd/records`, `GET /api/pd/records/:id`, and the actions `/pre`, `/rta-review`, `/complete`, `/g2`, `/post`) — faithful port of `records.php` + `record.php`. Role gates ported from `can()`/`require_role()` as `can_role()` (the listed roles, or COO). A new `records` read surface (operators/ceo/consultant, not members/lab techs). Records are opened from the idea's page. **Not carried over:** the delegated-sign-off email to the COO (notifications aren't ported — see #8 below) and the separate COO ratification action (that lives in the not-yet-ported Gate Log for G3–G6).

- **G3 beaker gate — the gate-log recorder + samples + lab tests** (`POST /api/pd/gates/decide`, `POST /api/pd/gates/:id/ratify`, `GET/POST /api/pd/samples`, `GET/POST /api/pd/tests`) — faithful port of `gates.php` + `samples.php` + `tests.php`. The committee **gate recorder** for G3–G6 (RTA/Custodian/COO), with **site-quorum** decisions flagged provisional and the **COO ratification** flow (which also stamps a matching delegated G2 on the Development Record). The **beaker-gate discipline**: a sample cannot be logged until the idea has a **G3 ADVANCE** in the gate log. Sample logging (QC Head team / Lab Technician / Custodian) with concurrency-safe `VAN-S-####` numbering, and lab tests with `T-####` numbering, driving the stage transitions `designed → sampled → tested`. New `samples` read surface (operators + Lab Technician; not CEO/consultant/member). The gate-log screen now carries the recorder + a COO ratification panel.

- **Pre-bench candidate screen + materials register** (`GET/POST /api/pd/materials`, `POST /api/pd/materials/conflicts`(+`/:id/confirm`), `GET /api/pd/candidates`, `GET/POST /api/pd/candidates/:hid/settings|add|decide|make`) — faithful port of `candidates.php` + `materials.php` + the `inc/screen.php` **arithmetic engine** (now `pd.screen_candidate()`). Pure mass balance, a target window, a landed-cost ceiling, and VAN's compatibility table — no chemistry, no AI. Computes weighted N/P₂O₅/S/Zn, ex-works cost `(RM + conversion)/(1 − loss)`, and **rupees per kg of P₂O₅** (the ranking number); verdict pass/borderline/fail with written reasons; **provisional** stamp whenever a placeholder price or assay is used. The **materials register** (edit by QC Head/Production/Custodian) carries every row's assay/cost **basis** so a placeholder can never pass as procurement data, plus the **compatibility table** (advisory until the QC Head confirms — then an `avoid` pair fails a candidate outright). The candidate lifecycle: set the route **bar** → **screen** a candidate (recipe on paper) → **select/reject** with a reason (QC Head; can't select past a FAIL) → **make** a sample (QC Head/Lab) — which is refused unless a **G3 ADVANCE** exists, and carries the micro-hypothesis + screened analysis into the sample record. Saving the bar **re-screens every candidate** on the route. The 10-row materials register is **seeded on migration** (all placeholder-priced), mirroring the PHP `setup.php`. New `candidates` read surface (operators + Lab Tech + CEO; not consultant/member).

- **Field trials (G5)** (`GET/POST /api/pd/trials`, `POST /api/pd/trials/:id/observe`, `POST /api/pd/trials/:id/update`) — faithful port of `trials.php`. Only hypotheses that survived the bench (stage `evaluated`/`field_trial`/`validated`) can be trialled; a trial is **designed** by Agronomy/Custodian with a `FT-YYYY-NN` code (concurrency-safe), needs a **G5 approval in the gate log before sowing** (the trials feed shows *awaiting G5* vs *G5 approved*), takes **season observations** (Agronomy/Custodian/RTA), and is **updated** through `designed → approved → running → harvested → analysed → closed` with sown/harvest dates, a result summary, and an advance/repeat/stop decision. New `trials` read surface (operators + CEO; not lab-tech/consultant/member). **Deferred:** the observation **photo upload** — same reason cowork flagged the Library, file handling gets one security pass later; observations are text-only for now and the `photo` column stays unused.

- **The Library** (`/api/pd/library…` incl. the auth-gated file serve) — faithful port of `library.php` + `libitem.php` + `file.php` + `inc/library.php`. The reading room: notes / links / uploaded documents, each stating **why** it's worth reading and its **evidence level** (VERIFIED / VALIDATE / OPEN); search + kind/evidence filters; **pin** an item to a route/project/problem and **comment** on it (anyone signed in); **archive/restore** by the Registrar (Custodian, with a reason, never deleted). Photos for field observations can now reuse this same store on a later pass.

New `dropbox` triage surface (Custodian/COO); the public submit endpoint and page sit outside auth by design.
